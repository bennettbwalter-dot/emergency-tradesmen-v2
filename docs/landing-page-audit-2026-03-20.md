# Landing Page Audit (UK/US) — March 20, 2026

## Scope

- Route and rendering: `src/pages/Index.tsx`
- Metadata component behavior: `src/components/SEO.tsx`
- Primary above-the-fold content: `src/components/sections/HeroSection.tsx`
- Secondary homepage content: `src/components/sections/SEOContentSection.tsx`
- Routing behavior affecting US/UK landing navigation: `src/App.tsx`, `src/components/Header.tsx`

## Executive Summary

The homepage has strong visual presentation and core metadata wiring, but there are critical SEO and crawlability risks around US path handling and incomplete internationalization metadata.

### Priority Overview

- **Critical**: US-prefixed internal links can route to `NotFound` despite being generated by navigation.
- **High**: No homepage `canonical` explicitly set in `Index.tsx`; relies on runtime URL inference.
- **High**: No `hreflang` alternate setup on homepage.
- **High**: Structured data uses placeholder-style phone values and city string formatting that may reduce trust quality.
- **Medium**: Home FAQ is hidden behind a toggle by default; less immediately indexable content exposure.
- **Medium**: Hero copy is broad and repetitive around “near me”; intent coverage can be expanded with service and locality specificity.

## Findings

### 1) Critical route mismatch for US-prefixed links

- Header builds `countryPrefix` as `/us` when selected locale is US on non-US domain.
- Multiple nav links use `${countryPrefix}/...`.
- Router explicitly sends `/us/*` to `NotFound`.

This can create internal links from the homepage that intentionally point to URLs the app immediately 404s.

## Impact

- Crawl waste and poor UX.
- Potential internal-link quality loss from homepage nav.

## Recommended Fix

Choose one strategy and apply consistently:

1. **Domain strategy (recommended)**: never generate `/us/...` links; route US to US domain paths without prefix.
2. **Prefix strategy**: keep `/us/...` links and restore full `/us` route support in router.

---

### 2) Homepage canonical not explicitly passed

`Index.tsx` sets `title` + `description` through `<SEO />`, but no `canonical` prop is passed.

## Impact

- Canonical depends on inferred runtime path.
- Harder to enforce strict UK root vs US domain canonical policy from the page layer.

## Recommended Fix

Pass explicit canonical from `Index.tsx`:

- UK domain: `/`
- US domain: `/`

(absolute domain should still be derived by `SEO.tsx` based on host).

---

### 3) Missing hreflang alternates on homepage

`SEO.tsx` supports `alternates`, but homepage does not supply them.

## Impact

- Weaker geo/language disambiguation for UK vs US equivalents.

## Recommended Fix

For homepage, supply alternates similar to:

- `en-GB` -> `https://emergencytradesmen.net/`
- `en-US` -> `https://emergencycontractors.net/`
- `x-default` -> preferred global default

---

### 4) Structured data quality gaps

`Index.tsx` uses `EmergencyService` JSON-LD with dynamic city text and static phone placeholders.

## Impact

- Placeholder style values can reduce trust/quality signals.
- `areaServed` currently includes display strings like `in {City}` / `Near You`; this is less normalized.

## Recommended Fix

- Replace phone placeholders with real trackable business numbers.
- Normalize `areaServed` to clean place names.
- Consider adding `WebSite` + `SearchAction` schema for homepage query intent.

---

### 5) FAQ content hidden by default

FAQ section is behind a toggle (`showFaq` false by default), meaning rich text is not immediately visible on first paint.

## Impact

- Lower direct content exposure for indexing and snippet extraction.

## Recommended Fix

- Keep top 3-5 FAQ items visible by default.
- Keep full accordion for expansion.

---

### 6) Hero and SEO section copy opportunities

Current homepage copy strongly emphasizes “near me,” but could better capture trade-intent variants and emergency symptom queries.

## Recommended Fix

Add naturally varied terms in visible copy blocks:

- emergency plumber/electrician/locksmith near me
- 24/7 emergency callout response times
- city/state intent variants for US
- regulatory trust hooks (market-appropriate)

## Landing Page Action Plan (Ordered)

1. Resolve `/us` route strategy mismatch (critical).
2. Add explicit homepage canonical + hreflang alternates.
3. Improve JSON-LD data quality (real numbers, normalized areas, optional `WebSite`).
4. Expose partial FAQ above fold.
5. Expand semantic keyword coverage in hero/supporting copy.

## Suggested Acceptance Criteria

- No homepage nav link points to a route that resolves to `NotFound`.
- Homepage has explicit canonical and valid `hreflang` alternates.
- JSON-LD validates without placeholder business data.
- At least 3 FAQ entries visible by default in rendered HTML.
- Homepage copy includes UK/US localized emergency-intent variants.
